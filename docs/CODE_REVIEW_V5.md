## 二、六大核心问题逐个拆解

### 🔴 问题 1：名录数据不更新（排名系统僵尸化）

**根因**：`rankingsV2()` 函数（server/index.js:1196）的设计有问题。

**具体表现**：
```javascript
// server/index.js:1207-1212
const fallback = [
  { name: "齐夏", score: 12880 },
  { name: "林檎", score: 9960 },
  { name: "乔家劲", score: 8800 },
  { name: "楚天秋", score: 7600 },
  { name: "列车长", score: 6400 }
];
```

- **6 个榜单中的 3 个**（daily_marks、cycle_total、zodiac_album）使用了 `rankingSnapshots` + 硬编码 fallback 混合。fallback 的分数固定为 NPC 的高分，玩家除非打出 12880+ 分否则永远进不了 daily_marks 的前 5。
- **daily_fog 榜** 用的是 `players` 实时数据 + fallback，但 fallback 被 `.reverse()` 后分数最低的 NPC 排第一。
- **beast_hall** 和 **zodiac_album** 几乎都是空白——`player.stats.beasts` 从未在任何地方被写入。

**验证方法**：打开榜单，看到永远是齐夏 12880 分排第一，你的分不管怎么打都在后面。

**修复指令**：
```
修改 rankingsV2()：
1. fallback 只在新游戏（排名快照为空）时使用，已有数据时不混入 NPC
2. beast_hall 改为从 rankingSnapshots 中筛选有 beast_event 标记的条目
3. zodiac_album 改为从 rankingSnapshots 中按 zodiac 分组取最高分
4. 每日结算（终焉列车到站）时将 daily 榜单写入 DB 并清理当日快照
```

### 🔴 问题 2：雾区买了商品毫无游戏内效果

**根因**：雾区商品只有买卖价格差这一个意义，持仓不会改变任何游戏行为。

**代码证据**（server/index.js:1791-1809）：
```javascript
// /api/fog/buy 的完整逻辑：
player.coins -= cost;           // 扣钱
player.stats.trades += 1;        // 计数+1
db.insert position...            // 写入持仓记录
pushMessage("雾区交易所", ...);   // 广播一条消息
```

**没有任何代码将持仓信息传递给试炼结算、方块属性、生肖奖励或任何其他系统。**

**设计文档要求 vs 现实**：

| 设计文档 | 当前实现 |
|----------|---------|
| 神兽遗物持仓影响当天四象神力 | 无 |
| 收集 12 生肖符咒解锁全图鉴 | 收集数据存在但无任何功能 |
| 规则碎片持仓揭示隐藏规则 | 无 |
| 商品类别影响试炼加成 | 无 |

**修复指令**：
```
1. 在 trial/report API（/api/trial/report）中加入 fogBonus 计算：
   - 持仓中有"神兽遗物"品类 → 当天对应神兽祝福概率 +20%
   - 持仓中有"生肖符咒"品类 → 当天生肖试炼分数 x1.15
   - 持仓中有"规则碎片"品类 → 情报购买后效果持续时间翻倍
   - 持仓中有"钟楼零件"品类 → 方块下落速度 x0.95

2. 在 fog/buy 返回时显示：
   "获得「{商品名}」——今日消行得分 +{x}%，已生效"

3. 前端在雾区面板中显示持仓的当前效果：
   "持有白虎利齿 → 当前：护盾上限 +1" 等
```

### 🔴 问题 3：情报买了不知道有什么用

**根因**：`applyOracleEffect()` 函数中 4/6 种效果类型写入的隐藏变量从未被其他系统消费。

**代码证据**（server/index.js:1304-1325）：

| 情报类型 | 实际效果 | 问题 |
|----------|---------|------|
| `market_preview` | 上调"神兽遗物"品类价格 12% | ✅ 有效 |
| `market_warning` | 下调"列车遗落物"品类价格 8% | ✅ 有效 |
| `battle_hint` | `player.stats.oracleBattleBoost += 1` | ❌ **从未被任何函数读取** |
| `zodiac_hint` | `player.stats.oracleZodiacBoost += 1` | ❌ **仅在 trial/report 中被减 1，但减了之后没产生任何效果** |
| `pact_hint` | `player.stats.oraclePactBoost += 1` | ⚠️ **仅在 addPactContribution 中读取，效果偏弱** |
| `train_hint` | 在 trainLog 插入一条记录 + 广播 | ⚠️ 有广播但无实际列车规则变化 |

**"买情报 → 出现一行字 → 什么也没发生" 就是当前体验。**

**修复指令**：
```
修复 applyOracleEffect：

1. battle_hint → 设置一个 3 局有效的 flag：
   player.stats.oracleBattleBoost = 3;
   在 trial/report 中：if (player.stats.oracleBattleBoost > 0) {
     player.stats.oracleBattleBoost--;
     本局第一次消 4 行额外 +500 分；
     前端显示"情报·第七列：四消加成已激活"
   }

2. zodiac_hint → 当天剩余时间内生效：
   player.stats.oracleZodiacBoost = true;
   // 在 trial/report 中，如果 oracleZodiacBoost 为 true：
   // 当日生肖方块出现概率翻倍
   前端显示"情报·生肖偏袒：{生肖}方块出现概率 x2"

3. 前端购买情报后必须显示具体效果文本：
   "你获得了「{情报名}」——未来 3 局内，四消额外获得 +500 刻痕"
   （而不是现在的一句"情报已写入铭刻之书"）
```

### 🔴 问题 4：广播没有上下文规则

**根因**：NPC 每人只有一句台词，不会根据日期/事件/玩家行为变化；系统消息全是"XX 做了 YY"，没有规则说明。

**代码证据**（server/index.js:2198-2201）：
```javascript
setInterval(() => {
  const npc = v2Npcs[Math.floor(Math.random() * v2Npcs.length)];
  pushMessage(npc.name, npc.line, "npc", ...);
}, 9000);

// 每个 NPC 只有一行 line：
{ name: "列车长", line: "下一站，不是你们的终点。" }
// 不管第 1 天还是第 10 天，白虎来了还是朱雀在烧，永远这句话。
```

**当前广播内容分析**：
```
全部消息类型：
- "XX 买入 雾区商品 x1"  → 纯系统通知，无趣
- "XX 卖出 雾区商品，收回 1230 刻痕" → 同上
- "XX 刻下 45 道钟痕"  → 同上
- NPC 重复一行话 → 无上下文

缺失的内容：
- 没有："今天是虎日——PVP 对抗奖励增强"   ← 规则不透明
- 没有："正午列车即将进站，雾区价格将剧烈波动"   ← 事件不预判
- 没有："XX 在虎日打出了 4消！双倍钟痕！"   ← 没有高光
- 没有："白虎低吼：果然是你。今日白虎殿堂新增一位。"   ← NPC 无变化
```

**修复指令**：
```
1. NPC 对话系统重写：
   - 每个 NPC 准备 5-10 句台词，按语境选择：
     * 晨钟时刻 → 列车长："今天的生肖是{生肖}。你知道这意味着什么。"
     * 正午时刻 → 白虎："雾区要动了。持仓的人，手别抖。"
     * 玩家打出四消 → 楚天秋广播："{玩家名}刚打破了一条规则。"
     * 玩家进白虎殿堂 → 白虎："牙不错。下一位。"
     * 无事件时 → 随机从台词库取（不再只有一句）

2. 上下文广播（与 train 系统绑定）：
   - 晨钟列车进站：推送当日规则的完整说明
     "【第{N}天 · {生肖}日】宣言：{declaration} | 规则：{zodiacEffect}"
   - 正午列车进站：推送雾区波动提醒
   - 黄昏列车进站：推送情报刷新提醒
   - 午夜列车进站：推送即将下架的商品
   - 终焉列车进站：推送今日排名预览

3. 高光广播：
   - 四消 → "战场广播：{玩家} 打出了毁灭四消！钟鸣响彻全城。"
   - 连消 5+ → 递增播报
   - 首次进入榜单前 3 → "{玩家} 杀入{榜单}第{N}名！"
```

### 🔴 问题 5：没有背景音乐

**根因**：`startBgm()` 存在但需手动点击"声场"按钮触发；BGM 不是真正的音乐，是用 Web Audio API 发两个音色每 1.8 秒循环一次，极其单调。

**代码证据**（v2-main.js:397-412）：
```javascript
function startBgm() {
  const ctx = ensureAudio(false);
  if (!ctx || audioState.bgmStarted) return;
  audioState.bgmStarted = true;
  let step = 0;
  const pulse = () => {
    const bass = [65, 73, 82, 98][step % 4];    // 4 个低音循环
    const bell = [392, 330, 440, 294, 523, 440, 392, 330][step % 8];  // 8 个钟声循环
    tone(bass, 1.8, "sine", 0.012);
    tone(bell, 0.22, "triangle", 0.012, 0.12);
    step += 1;
  };
  pulse();
  audioState.bgmTimer = setInterval(pulse, 1800);  // 每 1.8 秒两个音
}
```

这是一个极简的钟声节奏——有氛围但远不是"音乐"。没有旋律、没有变化、没有情绪起伏。

**而且整个项目目录中没有任何 .mp3 / .wav / .ogg 音频文件。**

**修复指令**：
```
方案 A：程序化 BGM（无需音频文件，立即可做）
1. 基于 Web Audio API 实现一个钟表主题 BGM 合成器：
   - 主旋律：用正弦波 + 三角波合成"钟声交响"（参考坂本龙一风格慢速钢琴）
   - 节奏层：用白噪声 + 滤波器模拟"秒针走动"和"齿轮咬合"
   - 环境层：低频嗡鸣代表"终焉钟楼"的持续性压迫感
   - 变化：根据游戏状态调整 BPM 和乐器组合：
     * 方块越堆越高 → BPM 加快、低频加强
     * 即将消行 → 加入高频泛音
     * 游戏结束 → 全体渐弱，只留一组钟鸣
     * 列车进站 → 插入汽笛音效 + 钟声
     * 白虎/朱雀日 → 对应的神兽主题变奏

2. 自动启动 BGM：
   - 页面加载后 3 秒自动开始播放（静音默认关）
   - 在页面角落放一个明显的"🔔 开启钟声"按钮
   - 第一次用户交互（点击方块/键盘操作）时自动激活 AudioContext

方案 B：加载真实音频（需准备素材）
1. 创建 public/audio/ 目录
2. 准备以下文件：
   - bgm_main.mp3：钟表行 × 终焉主题 BGM（3-5分钟循环）
   - bgm_trial.mp3：方块试炼战斗 BGM
   - bgm_train.mp3：列车进站音乐
   - sfx_clear.mp3：消行音效
   - sfx_tetris.mp3：四消特殊音效
   - sfx_harddrop.mp3：硬降音效
   - sfx_levelup.mp3：铭刻升级音效
   - sfx_whisper.mp3：终焉低语音效
   - sfx_beast.mp3：神兽降临音效
   - sfx_train_horn.mp3：列车汽笛
```

### 🔴 问题 6：没有爽点

**根因**：游戏反馈链不完整。玩家的投入（消行、雾区、情报、铭刻）和产出（反馈、视觉、音效、社交认可）之间缺少连接。

**具体诊断**：

| 玩家行为 | 当前反馈 | 应该有的反馈 |
|----------|---------|-------------|
| 消 1 行 | 分数+100（屏幕上方数字变化） | "+100" 浮出动画 + 轻钟声 + 一行火焰消散 |
| 消 2 行 | 分数+300 | "+300 × Combo!" + 钟声变大 + 两行消散 |
| 消 4 行 | 分数+800 | "四✨消✨！" 全屏闪烁 + 列车汽笛 + 全城广播 + 屏幕震动 |
| 连消(combo) | 无差异 | 每次 combo 音调升高，屏幕越来越亮，Combo 数字越滚越大 |
| 进入榜单前10 | 无通知 | "你的名字已被钟声传遍全城" + 全屏特效 + 广播播报 |
| 解锁铭刻 | "铭刻升级完成" toast | 铭刻之书翻页动画 + 新属性亮起 + 钟鸣 |
| 雾区大赚 | 数字变化 | "这笔交易会被记入钟楼史册" + 市场播报 + 持仓列表高亮闪烁 |
| 情报正确 | 无反馈 | "规则之眼：预言成真" + 屏幕边缘绿光 + 情报卡片发光 |
| 收集生肖 | 无反馈 | 每收集 3 个解锁一段专属旁白 + 图鉴发光 |
| 触发神兽 | 无反馈 | 神兽登场动画 + 当天特殊规则公告 + BGM 切换 |

**修复指令**：
```
按以下顺序实现"爽点金字塔"：

第一层（立即见效，2 人天）：
1. 消行动画：行不是直接消失，而是从中间裂开 → 光芒 → 消散，持续 300ms
2. 浮动分数：每个消行出 "+{分数}" 弹跳数字，四消用更大号金色字体
3. Combo 递进：
   Combo 1-2：普通音效
   Combo 3-4：音调升高 + 屏幕边缘脉冲
   Combo 5+：屏幕闪烁 + "🔥{N}连消！" + 列车汽笛
4. 屏幕震动：硬降和四消时触发 3-8px 快速震动

第二层（核心循环，3 人天）：
5. 高光广播机制：
   - 四消 → 全城广播
   - 榜单进入前 3 → NPC 点名祝贺
   - BOSS 击败 → 神兽降临广播
   - 收集完成 → 全图鉴广播
6. 列车到站事件视觉：
   - 屏幕顶部出现列车从右到左驶过的动画
   - 到站时广播内容在屏幕中央大字展示 3 秒
   - 雾区商品价格变动时，对应卡片闪烁红/绿
7. BGM 分层系统（见问题 5）

第三层（锦上添花，4 人天）：
8. 粒子效果：消行时碎片飞溅，四消时金粉飘落
9. 进度条动画：铭刻升级有填充动画，钟渊之路有石阶点亮
10. 收集系统反馈：每获得一个新收藏，弹出一个精致的"获得"卡片
    （类似原神/崩铁抽卡——这不只是"解锁了"，而是"你得到了"）
```
